# 爆款复刻方案复合节点设计

## 问题

当前系统把一个复刻方案中的每个镜头提示词、分段提示词、主提示词和策划记录都创建成独立画布节点。原片识别出 14 个动作节拍时，即使只生成一套方案，也会铺出 14 个镜头节点和多个辅助节点。“变体”因而被错误地表现为镜头级变化，同时增加画布噪音和跨镜头人物、商品、场景漂移风险。

## 目标模型

- 一个“复刻方案”代表一套完整的元素替换决定，对应一条最终视频任务。
- 变化发生在方案级：人物、商品、场景和内容先被一次性确定。
- 镜头级数据只描述如何把同一套元素方案执行到原片的动作节拍时间轴中，不允许每个镜头独立换人、换商品或换场景设定。
- 一个复刻方案在画布上只占一个复合节点；14 个动作节拍显示在节点内部的可滚动时间轴中。

## 数据结构

`ViralVideoPromptPlan` 增加以下必填字段：

- `elementPlan.characters`：本方案固定人物、外观、服装、关系与表演身份。
- `elementPlan.product`：固定商品或替换元素，以及参考图约束。
- `elementPlan.scenes`：场景映射、空间关系和跨镜头环境连续性。
- `elementPlan.content`：剧情内容、台词、字幕和商品植入方式。
- `continuityRules`：所有镜头共同遵守的人物、商品、服装、空间、动作和声音连续性规则。

`shotPrompts` 与 `segments` 继续保留，但只作为复合节点内部时间轴和最终主提示词的结构化输入，不再分别创建画布节点。

## 画布结构

每套成功方案创建一个固定尺寸的文本复合节点，元数据角色为 `variant`，内部包含：

1. 方案标题、动作节拍数量和“1 套方案 = 1 条视频”提示。
2. 人物、商品、场景、内容四项元素方案。
3. 全局连续性规则。
4. 按原片顺序排列的动作节拍时间轴，显示时间、原片动作和本方案执行提示词。
5. 可编辑的完整成片主提示词。

画布只连接“拉片分析 → 复刻方案 → 完整成片”；上传替换元素图时再连接“替换元素图 → 复刻方案/成片”。

## 生成链路

- “生成套数”改名为“复刻方案数”。
- 文本模型按方案数独立返回完整 `ViralVideoPromptPlan`，每个响应内部一次性确定四类元素和连续性规则。
- 每套方案只创建一个复合节点。
- 成片阶段直接从复合节点元数据读取完整计划，在一条视频请求中组合全部动作节拍；镜头数不会增加付费视频任务数。
- N 套方案对应 N 次文本策划和 N 条付费视频；单套方案无论包含多少动作节拍都只对应一条视频。

## 兼容与清理

- 打开已有画布时，把当前有效的旧式镜头/分段/主提示词/记录节点按 `planId` 自动折叠为一个复合方案节点，不重新调用模型。
- 迁移时使用旧记录中的计划和用户编辑后的主提示词；旧计划缺少新增元素字段时，从已有原创规则、商品连续性和主提示词生成保守的兼容摘要。
- 删除旧式提示词节点并重连分析、替换元素和已有成片连接。
- 重新生成方案或修改复刻设置时，清除已经失效的旧提示词节点，避免画布继续堆积。

## 验收标准

- 一套包含 14 个动作节拍的方案只创建一个复合方案节点。
- 复合节点内部完整显示 14 条时间轴记录。
- 人物、商品、场景和内容是方案级字段，镜头提示词明确继承它们。
- 编辑主提示词后，成片请求使用编辑后的内容。
- 一个方案只提交一个完整视频任务；多分段、多镜头不增加任务数。
- 旧画布刷新后自动折叠有效方案，不需要重新付费分析或生成。
