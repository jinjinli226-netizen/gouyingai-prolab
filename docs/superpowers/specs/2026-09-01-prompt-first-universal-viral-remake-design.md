# 提示词优先的通用爆款复刻工作流设计

## 目标

把 GouYingAI 无限画布中的“爆款复刻”收敛为一个稳定、通用、可验证的工作流：用户只需上传一条参考视频，并可选上传人物、商品、场景、服装或道具素材；系统先把原片重建为一份忠于原片的标准导演提示词，再只替换用户指定的对象，最后编译成目标视频模型可以执行的提示词并生成完整视频。

本工作流以提示词为主。参考视频主要用于理解和校验，不假设目标视频模型支持视频参考。系统不能把“复刻”变成二次创作，也不能要求用户先写商品描述或人工改造脚本。

## 复刻口径

复刻保留原片可观察到的动态结构，包括：

- 事件发生顺序、动作因果和物体状态变化。
- 各阶段相对时长、节奏密度和关键瞬间的位置。
- 镜头连续或切换关系、视角变化和镜头运动。
- 人物、物品与环境在动作过程中的空间关系。
- 原片确实存在的对白、字幕、音乐和音效节点。
- 用户没有明确要求修改的其他可观察内容。

默认只改变已绑定的对象身份与外观。原片中的“物体被挤出、坠落并撞入容器”不能因为换成手机壳，就被改写成“角色用手把手机壳安装到手机上”。

复刻不承诺逐像素复制。产品验收目标是同一套母版测试 10 次，至少 8 次达到内部 90 分复刻评分；这是工作流认证指标，不是单次生成的无条件结果承诺。

## 现状诊断

当前链路实际是：

```text
拉片分析 -> 创意策划器重新编写方案 -> 生成提示词 -> 视频生成
```

它存在三个根因：

1. 策划器被要求“原创重制”和重新发明人物、场景、道具与声音，拥有改写动作、因果和时间轴的权限。
2. 覆盖门禁只验证原事件 ID 是否被引用，没有比较事件动作的语义，因此“排出并坠落”改成“拿起并安装”仍会被判定为覆盖成功。
3. `hook`、`spectacle`、`reveal`、`product_proof`、`cta` 等固定分类被当成所有视频的必备结构，导致安静展示、ASMR、连续表演、口播和生活记录也被强行套入带货叙事模板。

目标链路改为：

```text
原片证据
  -> 原片重建提示词
  -> 第二次观看与校验修复
  -> 对象占位符与替换绑定
  -> 可选的局部用户改动
  -> 语义差异门禁
  -> 目标模型提示词编译
  -> 完整视频任务
```

分析之后不再经过一个拥有自由创作权的全片策划器。

## 产品原则

### 只有一种用户模式

界面只有“爆款复刻”，不暴露结构复刻、创意改编、镜头复刻等多种模式。系统内部可以根据模型能力和视频复杂度选择执行路径，但不能让用户先理解技术路线。

### 不要求用户写描述

- 商品描述不是必填项。
- “改造要求”改名为“额外改动（可选）”。
- 留空表示：完整保留原片动态，只替换已绑定对象。
- 用户上传素材后，由系统识别对象种类、外观事实和对应关系。

### 不预设叙事类型

分析提示词不能要求每条视频都有冲突、反转、揭晓、商品证明或 CTA。只有原片确实存在时才记录这些内容。

### 不把动态视频压成静态表单

朝向、姿态、表情、构图、运镜、光线等信息只在影响当前动作或连续性时写入连续描述，不要求每个时间单元机械填写一套固定字段。核心产物是一份动态导演提示词，不是一组静态标签。

## 保留与重做

### 保留

- 完整视频原生理解；模型不支持视频输入时使用时间证据图、镜头变化帧和高运动帧回退。
- 原片对象识别、上传素材识别、对象指纹、多角度参考图和显式替换绑定。
- 参考视频、复刻素材、复刻母版、批量生产、成片结果库五类主卡片。
- 一套候选只创建一个完整付费视频任务；时间单元不拆成多个视频任务。
- 现有批量实例编译、Gateway 后台有界队列、费用预估、持久化、暂停、恢复、重试和结果库。
- 用户确认的替换关系优先于自动识别。

### 重做

- 用“原片重建提示词”替换当前固定营销维度的分析结果。
- 删除分析后的自由创意重编，改为确定性的占位符替换和局部补丁。
- 用第二次视频校验修复替换当前仅检查字段完整性的修复。
- 用动作语义差异门禁替换只统计事件 ID 的覆盖门禁。
- 将最终生成逻辑改成从唯一标准提示词编译到目标模型，而不是重新规划全片。
- 将“变体”限定为用户声明的批量变量槽位，不再把镜头或时间单元称为变体。

## 核心数据模型

### 原片重建结果

```ts
type SourceReconstruction = {
  id: string;
  sourceVideoId: string;
  durationSeconds: number;
  aspectRatio: string;
  entities: SourceEntity[];
  timelineUnits: ReconstructionTimelineUnit[];
  canonicalPrompt: string;
  evidence: SourceEvidence[];
  verification: ReconstructionVerification;
  version: 2;
};
```

`canonicalPrompt` 是唯一的原片标准导演提示词。它在上传替换素材之前生成，之后不能由生成模型自由改写。

### 自适应时间单元

```ts
type ReconstructionTimelineUnit = {
  id: string;
  startSeconds: number;
  endSeconds: number;
  parentShotIndex: number;
  sourceGroundedDirection: string;
  placeholderIds: string[];
  evidenceIds: string[];
};
```

- 时间单元按可观察变化自适应划分，不按固定秒数、平均采样间隔或固定模板切分。
- `sourceGroundedDirection` 使用连续的导演语言描述这段时间实际发生的事情，允许包含动作、物理变化、镜头、声音、文字和连续性，但只写当前视频需要的内容。
- 一镜到底可以有多个连续时间单元；多次切镜也可以按真实边界分开。
- 时间单元是提示词和校验的容器，不是视频生成任务。

### 对象与占位符

每个可替换对象获得稳定占位符，例如 `@角色1`、`@商品1`、`@场景1`、`@道具1`。原片重建提示词直接引用占位符，不在替换时重新生成动作文本。

```ts
type PromptEntityBinding = {
  placeholderId: string;
  sourceEntityId: string;
  replacementEntityId?: string;
  status: "source-only" | "auto-bound" | "user-confirmed" | "ambiguous";
};
```

对象描述分为两层：

- `identityFacts`：外观、材质、颜色、标记、服装或环境事实，可以随绑定替换。
- `behavioralRole`：对象在原片中做什么、被如何作用、与其他对象的关系，只能随显式用户改动变化。

### 局部改动补丁

```ts
type PromptPatch = {
  id: string;
  reason: "explicit-user-change";
  affectedTimelineUnitIds: string[];
  before: string;
  after: string;
};
```

“额外改动（可选）”非空时，AI 只能针对受影响时间单元生成补丁。系统保存修改前后内容并向用户展示影响范围，不能借此重新规划整条视频。

### 语义差异报告

```ts
type PromptDiffReport = {
  allowedChanges: PromptDifference[];
  forbiddenChanges: PromptDifference[];
  passed: boolean;
  summary: string;
};
```

允许变化的来源只有：

1. 已确认对象绑定带来的身份和外观替换。
2. 用户在“额外改动”中明确授权的局部补丁。
3. 目标模型语法格式变化，但不能改变语义。

时间顺序、动作因果、物体状态变化、镜头关系、声音节点和可见文字若在上述范围之外发生改变，必须阻止付费提交。

## 工作流

### 1. 原片证据准备

优先把完整视频直接交给支持视频理解的模型，并要求读取视觉、时间和音轨。若上游不支持视频输入，则生成带时间戳的时序证据：

- 全片基础覆盖帧。
- 真实切镜或明显时空跳变附近的帧。
- 高运动、高变化和物体状态变化附近的帧。
- 需要时使用少量短片段，而不是把任意 24 张独立图片直接堆给模型。

多帧回退可以使用带编号和时间戳的联系表，但必须保留原始顺序与间隔信息。无法读取声音时明确标记，不允许猜测对白、音乐或音效。

### 2. 原片重建

第一次模型调用只做原片重建：

1. 识别真实镜头边界和镜头内部的可观察动态变化。
2. 识别人物、商品、场景、服装、道具、动物和车辆等对象。
3. 建立稳定占位符。
4. 生成覆盖 0 秒到片尾的自适应时间单元。
5. 汇总为一份可直接用于重新生成原片的标准导演提示词。

提示词禁止：

- 按固定秒数切片。
- 强制输出钩子、冲突、反转、揭晓、卖点或 CTA。
- 根据常识补全原片没有展示的行为。
- 把顺序动作合并成含糊的一句话。
- 因为未来可能替换商品而提前改写物理动作。

### 3. 第二次观看与校验修复

第二次模型调用同时接收同一份原片证据和第一次生成的重建结果，专门回答：

- 是否漏掉可观察事件、动作阶段或片尾。
- 是否发明了原片不存在的人物、物品、行为、字幕或声音。
- 是否改变了事件顺序、动作主体、受力关系、状态变化或镜头运动。
- 时间位置和持续时间是否明显漂移。
- 连续镜头是否被误写为切镜，或真实切镜是否被合并。

校验器输出问题清单、置信度和修复后的完整重建提示词。修复最多执行一次；仍不合格时停止，不开放视频生成。

这一步必须在用户上传替换素材之前也能独立完成，因此重建质量不受目标商品影响。

### 4. 对象识别与替换绑定

上传素材是可选的。系统识别素材后建立明确映射，例如：

```text
@角色1：原片中的拟人牛肉生物 -> 用户上传的微型红蓝蒙面英雄角色
@商品1：原片中的厚切牛排 -> 用户上传的手机壳
@道具1：原片中的铁锅 -> 用户上传的手机
```

替换只更新占位符对应的身份与外观，不重新生成时间轴和动作。多对象或低置信度时显示待确认；用户直接在某对象卡片下上传素材视为确认。未替换对象继续沿用原片对象描述。

### 5. 可选局部改动

用户不填写任何文字即可复刻。只有用户明确提出新动作或新剧情时才创建 `PromptPatch`。

局部补丁必须：

- 标明受影响的时间单元。
- 保留没有被授权修改的前后时间单元。
- 重新校验与前后状态的连续性。
- 在生成前摘要中清楚显示“额外改变了什么”。

### 6. 语义差异门禁

系统从标准提示词构建“替换后标准提示词”，并比较二者：

- 占位符身份和外观差异应与绑定清单一一对应。
- 动作动词、动作主体和受体、事件顺序、受力与状态变化默认必须保持。
- 时间区间与镜头结构默认必须保持。
- 对白、字幕、音乐和音效默认必须保持；目标语言调整属于显式配置差异。
- 用户局部补丁之外出现的动作变化均为禁止差异。

门禁失败时显示具体差异，例如“原片：@角色1 将 @商品1 从身体后方挤出；待生成：@角色1 用手把 @商品1 安装到 @道具1”，并禁止创建视频任务。

### 7. 目标模型编译

通过门禁后，编译器把同一份替换后标准提示词转换成 H3、Seedance、Veo 或其他模型的输入格式。编译器只能做：

- 模型语法和长度适配。
- 按稳定顺序附加参考图和对象绑定清单。
- 加入由原片事实推导出的连续性与负面约束。
- 根据模型要求组织时间段，但不得重新规划动作。

目标时长默认等于原片时长。模型不支持该时长时，在付费提交前明确阻止或要求切换可用模型，不能静默拉长、压缩或截断。用户主动修改时长时，必须作为显式局部改动重新通过差异门禁。

### 8. 生成与批量

单条和批量共用同一份已验证标准提示词：

- 一条候选对应一个完整视频任务。
- 生成数量默认 1，可配置 1–1000。
- 批量不会重新拉片或重新规划动作。
- 固定对象绑定、标准时间轴和未授权内容在所有候选中不可变。
- 只有用户声明的变量槽位可以变化，例如人物、商品颜色、场景装饰、服装或摄影风格；一个槽位的选择在整条候选视频中固定。
- 不声明变量槽位时，候选间只允许模型随机种子造成的自然微差。

## 提示词分层

系统内部只维护四层提示词：

1. **原片重建提示词**：描述原片本身，是事实层和唯一母版。
2. **替换绑定清单**：只描述每个占位符替换成什么。
3. **用户局部补丁**：可选，只描述用户明确要求修改的部分。
4. **模型编译结果**：把前三层转为目标模型方言，不增加创意。

禁止再引入一个“根据以上内容创作新方案”的全片策划提示词。

## 画布交互

画布继续保留五类主卡片：

1. **参考视频**：上传、更换和预览原片。
2. **复刻素材与对象识别**：对象卡片、参考图、自动绑定、待确认状态和“额外改动（可选）”。
3. **已验证复刻母版**：默认显示精简摘要、时间轴代表图和校验状态；可展开查看标准导演提示词与差异报告。
4. **批量生产**：数量、允许变化槽位、模型、费用、队列和状态。
5. **成片结果库**：集中显示候选、评分、预览、筛选、重试和下载。

主按钮按状态变化：

```text
开始识别与重建
  -> 正在校验原片
  -> 生成复刻视频
  -> 运行进度
```

提交前只需向用户展示三项摘要：

- 保留：原片动作、时间轴、镜头、声音等。
- 替换：对象 A -> 对象 B。
- 额外改变：无，或列出用户授权的局部补丁。

用户不需要阅读或编写完整提示词，但可以展开检查和手动编辑。手动编辑视为显式补丁，必须重新运行差异门禁。

## 状态机

```text
source_uploaded
  -> reconstructing
  -> verifying
  -> binding_ready
  -> compiling
  -> diff_checking
  -> ready_to_submit
  -> running
  -> partially_completed | completed | paused | failed
```

- 更换原片：使重建、校验、绑定、编译和未提交批次失效。
- 修改替换素材：只使相关绑定、编译和未提交实例失效，不重新拉片。
- 修改额外改动：重建结果不失效，只重新生成局部补丁、连续性校验和差异报告。
- 修改批量数量或变量槽位：只重新编译实例清单。
- 已经完成的历史视频不因配置变化被删除。

## 失败与费用保护

- 原片输入无法读取：不创建空分析结果，显示具体上游错误。
- 只能使用抽帧证据：标注能力降级和声音置信度。
- 第二次校验仍不合格：阻止生成并显示遗漏或矛盾。
- 替换关系存在歧义：只阻止相关对象，要求确认；单一明确对象可自动绑定。
- 语义差异门禁失败：禁止付费提交。
- 模型时长、画幅、参考图数量或音频能力不匹配：在付费前阻止。
- 点击生成必须显示候选数量、单条预计费用和总预计费用。
- 默认不自动试跑、不自动扩产、不自动付费重试。
- 创建批次使用幂等请求 ID，刷新或重复点击不得重复收费。

## 生成后质检

成片仍可进行轻量反向拉片，但评分维度改为与标准重建提示词直接对齐：

- 时间单元覆盖与顺序。
- 动作主体、受体、因果和状态变化。
- 人物与替换对象一致性。
- 镜头关系和相对时长。
- 可确认的对白、字幕、音乐与音效。
- 物理连续性和严重视觉错误。

任一不可缺失的动作阶段丢失，或动作语义发生反转时，不得判为 90 分以上。自动重试次数默认 0，只有用户授权后才产生额外费用。

## 测试与验收

### 单元测试

- 自适应时间单元不按固定秒数生成。
- 原片没有冲突、反转、揭晓或 CTA 时，分析结果仍可通过。
- 原片重建在没有替换素材时即可完成并通过校验。
- 替换绑定只改变占位符的身份和外观，不改变时间轴或动作文本。
- “挤出/坠落/撞入”被改成“拿起/安装”时，差异门禁必须失败。
- 用户明确要求改变动作时，只对应时间单元形成允许补丁。
- 一个视频有 14 个时间单元时仍只创建一个完整视频任务。
- 生成数量从 1 改到 1000 不重新拉片、不重新生成母版。

### 多类型固定样例

至少使用以下不同视频验证通用性：

- 安静的商品旋转或细节展示。
- 单人口播带货。
- ASMR 或无对白制作过程。
- 一镜到底的物理动作或视觉奇观。
- 多切镜蒙太奇。
- 服装试穿或换装。

任何样例都不得因为缺少固定营销标签而失败。

### 集成验收

1. 用户只上传原片也能得到已验证的原片重建提示词。
2. 用户追加一组或多组素材后，系统自动识别并建立可检查的绑定。
3. 用户留空“额外改动”时，提交摘要明确显示“额外改变：无”。
4. 所有禁止差异在付费任务创建前被拦截。
5. 编译到不同视频模型时，标准时间轴和动作语义保持相同。
6. 批量候选共享同一母版，并只在声明槽位内变化。
7. 生成后评分能识别关键动作缺失、动作反转和对象漂移。
8. 通过 10 次认证测试时，至少 8 次达到 90 分后才标记该模型与母版组合为“可扩产”。

## 代码落点

现有模块按以下职责调整：

- `viral-video-remake-workflow.ts`：生成和解析 `SourceReconstruction`，执行第二次观看校验；移除固定营销功能的硬性要求。
- `viral-video-domain.ts`：新增重建、占位符、局部补丁和语义差异类型；旧营销事件枚举不再作为通用主模型。
- `viral-video-template.ts`：母版直接引用已验证的标准提示词；覆盖报告升级为动作语义差异报告，不再用事件 ID 计数代替忠实度。
- `viral-video-generation.ts`：只负责编译标准提示词、绑定清单和已授权补丁；禁止调用自由重编策划器。
- `viral-video-batch-compiler.ts`：继续复用，但标准提示词、对象绑定和时间轴为不可变输入，只有声明变量槽位可变化。
- 现有 Gateway 队列与结果库保持不变，仅保存新的母版版本和差异报告引用。

项目尚未发布，本次直接使用 `version: 2` 替换旧的内部母版结构，不为旧画布编写长期迁移层；旧画布可显示“使用旧版母版，请重新分析”。

## 不在本轮范围

- 承诺逐像素或逐帧完全相同。
- 依赖所有视频模型都支持原片视频参考。
- 要求用户填写商品描述或改造脚本。
- 为不同视频类型提供五种用户模式。
- 把每个时间单元拆成独立付费视频任务。
- 默认强制生成 10 条或 1000 条。
- 自动把未授权的“更适合商品”动作加入原片。
