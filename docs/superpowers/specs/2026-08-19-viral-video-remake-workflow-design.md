# 爆款复刻无限画布工作流设计

## 目标

在现有“AI批量带货系统”中新增独立的“爆款复刻”入口。用户上传一条爆款参考视频后，系统使用具备视频理解能力的文本模型完成真实拉片，生成逐镜头分析和逐镜头复刻提示词，再调用视频模型生成新的成片或分段视频。

该工作流复用现有无限画布、浏览器本地媒体存储、文本模型和视频模型接口，但不复用普通“反推提示词”流程，也不与已有 AI 硬广、视觉种草、剧情带货、痛点对比和混剪解说混在一起。

## 核心原则

- 先分析真实视频，再生成提示词，最后生成视频；不能在没有拉片结果时套固定模板。
- 镜头数量、切镜时间、人物数量、场景数量和叙事结构全部由 AI 根据上传视频动态识别。
- 不固定在某个秒点换场，不预设固定三段式或固定主角。
- 复刻的是构图、节奏、叙事结构、镜头语言、光影色彩和声音策略，不直接复制原人物、品牌、字幕、Logo 或受版权保护的独特素材。
- 新商品图和替换要求为可选输入。上传后，最终提示词以新商品为唯一商品事实来源；未上传时也不得主动复刻原视频中的品牌与可识别知识产权。
- 拉片、提示词和最终生成结果都保留在画布节点中，可查看、编辑、单独重试和继续连线。

## 入口设计

在 `/ecommerce` 的“视频带货工作流”区域新增独立条目：

- 标题：`爆款复刻`
- 副标题：`上传参考视频，AI 拉片后生成逐镜头复刻提示词和新视频。`
- 图标：视频扫描或时间轴类型图标。
- 按钮：`进入复刻工作流`

点击后创建新的专用画布项目，项目 `workflow.kind` 使用独立值 `viral-video-remake`，不扩展现有 `ecommerce-video` 分类枚举。

## 初始画布

初始画布只创建两个输入节点：

1. `上传爆款参考视频`：必填视频节点。
2. `上传新商品图`：可选图片节点，用于替换原视频中的商品。

顶部专用工具条提供：

- 当前步骤和状态。
- `上传参考视频`。
- `上传新商品图`。
- 替换要求文本输入，例如“保留开箱结构，替换为我的护肤品，不使用原品牌字幕”。
- `开始拉片分析`。
- 分析完成后的 `生成分镜提示词`。
- 提示词完成后的 `一键生成视频`。
- 当前任务进度、成功数和失败数。

用户可以不上传新商品图，直接分析和复刻镜头结构；但最终提示词仍必须去除原视频中的品牌、人物身份和受保护素材。

## 分步流程

### 第一步：上传视频

参考视频通过现有媒体上传逻辑写入浏览器 `media_files`，视频节点保存 `storageKey`、`mimeType`、`bytes`、`durationMs` 和可播放的本地 URL。

开始分析前检查：

- 已上传且能读取视频。
- 已配置文本模型。
- 文本模型采用当前支持视频理解的调用格式。
- 视频可以转换为模型可访问的 `video_url` 或 Data URI。

如果模型不支持视频理解、视频读取失败或上游拒绝文件，直接显示真实错误，不退化为根据文件名或封面猜测。

### 第二步：AI 拉片分析

系统向文本模型提交原视频和完整拉片提示词，要求只返回可解析 JSON。一次分析必须覆盖完整时间轴，不能只描述开头几帧。

分析维度：

1. 时间轴信息：每个镜头的开始时间、结束时间和时长。
2. 叙事要素：场景、可见角色、动作、对白、字幕、关键信息和镜头目的。
3. 镜头语言：景别、构图、机位、角度、镜头类型、焦段感、运镜、对焦、景深。
4. 影像处理：光影、色彩、质感、曝光、背景处理、转场和后期观感。
5. 声音设计：对白、旁白、音乐、音效、环境声、节奏点及其叙事作用。
6. 整体风格：前三秒钩子、剪辑节奏、叙事结构、视觉规律、爆点和可迁移核心。

页面展示接近用户提供的 Oiioii 拉片信息密度，但使用画布节点承载数据。完整分析节点位于原视频右侧，并按镜头分段显示以下字段：

- 镜头编号与代表帧。
- 画面描述。
- 开始、结束、时长。
- 场景与角色。
- 景别、构图、镜头类型、运镜、焦距与景深。
- 光影与色调。
- 音乐、音效、对白或旁白。
- 镜头叙事功能。
- 可替换元素与必须保留的结构。

代表帧优先在浏览器本地按镜头中点时间截取，不要求 AI 返回图片。

### 拉片进度

工具条显示用户提供的阶段文案：

- `时间轴信息提取：正在标注每个镜头的开始时间、结束时间与时长。`
- `叙事要素解析：正在识别场景、可见角色、对白与关键叙事信息。`
- `镜头语言解构：正在检查景别、构图、画框、机位与运镜方式。`
- `视觉风格提炼：正在分析光影、色彩、景深、剪辑节奏与整体观感。`
- `声音与叙事洞察：正在检查音乐、音效、镜头目的与故事推进。`
- `拉片结果整理：正在校验时间轴连续性并创建画布节点。`

进度值代表前端工作流阶段，不伪装成模型内部的真实推理百分比。等待单次 AI 分析响应期间，阶段文案可以轮换，但进度在响应返回前不显示为 100%；解析和节点创建成功后才完成分析阶段。

## 拉片数据结构

```ts
type ViralVideoRemakeWorkflowState = {
  kind: "viral-video-remake";
  sourceVideoNodeId: string;
  productNodeId: string;
  replacementBrief: string;
  analysisNodeId?: string;
  masterPromptNodeId?: string;
  batchCount: number;
};

type ViralVideoAnalysis = {
  title: string;
  durationSeconds: number;
  aspectRatio: string;
  hook: string;
  narrativeStructure: string;
  editRhythm: string;
  visualStyle: string;
  soundStrategy: string;
  transferableCore: string;
  shots: ViralVideoShot[];
};

type ViralVideoShot = {
  index: number;
  startSeconds: number;
  endSeconds: number;
  durationSeconds: number;
  frameDescription: string;
  scene: string;
  characters: string;
  action: string;
  dialogue: string;
  visibleText: string;
  narrativePurpose: string;
  shotSize: string;
  composition: string;
  cameraAngle: string;
  lensAndFocus: string;
  cameraMovement: string;
  lightingAndColor: string;
  transition: string;
  musicAndSound: string;
  replaceableElements: string;
  structuralMustKeep: string;
};
```

解析时必须校验：

- `shots` 至少有一项。
- 镜头编号连续。
- 每项 `endSeconds > startSeconds`。
- 时间轴按开始时间升序。
- 相邻镜头不能产生明显重叠。
- 最后一个镜头结束时间不能明显超过视频总时长。
- 必填分析字段不能为空。

返回无法解析或校验失败时，保留错误信息并允许重新分析；不生成假的默认镜头。

## 第三步：生成分镜提示词

拉片完成后，用户点击 `生成分镜提示词`。系统将结构化拉片结果、新商品图（如有）和替换要求发送给文本模型，生成：

- 每个镜头一条完整英文视频提示词。
- 一个整片复刻主提示词。
- 原创化与商品一致性约束。
- 需要保留的时间、节奏和转场关系。
- 建议的视频生成分段方案。

提示词生成是独立于拉片的第二次 AI 请求，便于用户先检查拉片是否准确，再决定是否进入生成阶段。

每个镜头提示词必须包含：

- 目标时长。
- 原创场景、人物或手部设定。
- 新商品的外观保持要求；未上传商品图时使用无品牌通用对象。
- 画面动作和叙事目的。
- 景别、构图、机位、焦段感、运镜、景深。
- 光影、色彩、质感和转场。
- 对白、旁白、音乐、音效和节奏点。
- 禁止复制的原品牌、人物、字幕、Logo 和 IP。

画布布局按镜头向下排列，每一行先包含：

```text
镜头分析摘要 → 完整分镜提示词
```

同时创建一个 `整片复刻主提示词` 文本节点，汇总全部镜头顺序和跨镜头一致性。文本节点的 `metadata.prompt` 保存实际提交给模型的完整提示词，用户能直接查看和编辑。最终视频结果按生成分段创建，不强制每个原始镜头各生成一条视频。

## 第四步：直接生成视频

用户点击 `一键生成视频` 后，系统按照提示词分段方案创建视频生成任务：

- 原视频总时长不超过当前视频模型单任务上限时，优先使用整片主提示词生成一条完整视频。
- 原视频超过单任务上限时，按镜头边界分成多个不超过模型上限的片段，分别创建视频结果节点。
- 不在一个镜头内部强行截断；无法满足时由提示词策划阶段重新调整分段。
- 新商品图作为视频参考图传入；原爆款视频只用于理解和结构提取，不直接作为最终视频生成参考，避免复制原始人物与素材。
- 每个任务的完整提示词、模型、时长、状态和错误都保存在对应节点。
- 批量生成并发沿用现有视频工作流上限，最多同时执行 3 个任务。

当前工作流不负责自动拼接多个生成片段。超过单任务上限时，画布保留按顺序排列的分段视频，后续可另接视频拼接能力。

`batchCount` 表示基于同一拉片结构生成几套原创变体，输入范围为 1-100。不同变体保留同一镜头节奏和叙事功能，但重新生成场景细节、人物外观、动作表达和声音设计；同一套内部保持连续性。实际视频任务数等于 `batchCount × 生成分段数`，总任务数最多 100；超过时工具条直接提示用户减少变体数量。

## 节点和连线布局

初始节点位于左侧：

```text
爆款参考视频
新商品图（可选）
```

分析完成后：

```text
爆款参考视频 ──→ 完整拉片分析
```

提示词完成后，每个镜头形成一行：

```text
完整拉片分析 ──→ 镜头 N 分析摘要 ──→ 镜头 N 完整提示词
新商品图 ───────────────────────────────────────↗
```

所有镜头提示词连接到 `整片复刻主提示词`。如果生成整片，主提示词连接到一个整片视频结果；如果需要分段，主提示词连接到按顺序排列的多个分段视频结果。画布自动定位到最新创建的结果区域，但用户仍可自由缩放、编辑、删除和重新连线。

## 组件边界

- `web/src/lib/canvas/viral-video-remake-workflow.ts`：工作流项目构建、AI 提示词、JSON 解析、格式化和分段规则。
- `web/src/components/canvas/viral-video-remake-canvas-bar.tsx`：专用顶部工具条和分步按钮。

修改文件建议：

- `web/src/types/canvas.ts`：新增工作流状态和拉片类型。
- `web/src/pages/ecommerce/index.tsx`：新增独立入口。
- `web/src/pages/canvas/project.tsx`：接入上传、分析、提示词和视频生成流程。
- `docs/content/docs/progress/pending-test.mdx`：记录需要人工验证的完整链路。
- `CHANGELOG.md`：在 `Unreleased` 中归纳新增工作流。

不新增后端接口，不修改 Gateway 路由，不恢复前台渠道配置。所有 AI 请求继续使用当前管理后台发布的文本模型和视频模型。

## 错误处理

- 未上传参考视频：提示“请先上传爆款参考视频”。
- 文本模型未配置：打开现有模型配置提示。
- 模型不支持视频理解：显示真实上游错误，并建议更换具备视频理解能力的文本模型。
- 视频过大或格式不支持：保留原节点，提示重新压缩或更换格式。
- JSON 解析失败：分析节点显示原始错误，不生成默认镜头。
- 时间轴不连续或越界：说明具体镜头编号并允许重新分析。
- 商品图读取失败：分析仍可保留，但提示词生成和视频生成停止。
- 某个视频任务失败：只标记对应结果节点失败，不取消其他任务；支持单节点重试。
- 用户取消：停止尚未提交的任务，保留已经完成的分析、提示词和视频。

## 验收标准

1. `/ecommerce` 出现独立“爆款复刻”入口。
2. 进入后只显示参考视频和可选商品图两个初始节点。
3. 未上传视频不能开始拉片。
4. 拉片结果来自实际上传视频，镜头数和切点不使用固定模板。
5. 每个镜头包含时间、叙事、镜头语言、影像处理和声音字段。
6. 分析阶段显示清晰的阶段文案，但不伪造模型内部精确进度。
7. 拉片完成前不能生成分镜提示词。
8. 每个镜头的完整提示词在画布中可见、可编辑。
9. 上传新商品图后，提示词明确保持新商品外观并去除原品牌元素。
10. 不超过模型时长上限时可以生成整片；超过时按镜头边界分段。
11. 所有视频结果节点保留实际提示词、状态和失败原因，并可单独重试。
12. 同一拉片可选择生成 1-100 套原创变体，实际生成任务总数不超过 100，浏览器并发最多 3 个视频任务。
13. 现有五类带货、项目海报、珠宝商品图和自由画布功能不受影响。

## 本期不做

- 不做自动下载或抓取第三方平台爆款视频。
- 不做爆款排行榜、数据爬取或平台账号发布。
- 不做自动剪辑拼接、配乐版权库或成片导出工程。
- 不做多人云端共享项目库。
- 不保证所有文本模型都具备完整视频理解能力。
- 不直接克隆原视频人物、品牌、字幕、Logo、声音或受保护 IP。
