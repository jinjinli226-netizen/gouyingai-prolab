# 爆款复刻拉片分析复合节点设计

## 目标

把爆款复刻现有的“拉片总览文本节点 + 每镜头代表帧节点 + 每镜头分析文本节点”改为一个只读的大型复合节点。该节点直接位于无限画布中，集中展示完整拉片结果，视觉结构参考用户提供的 OiiOii 拉片分析截图，但沿用 GouYingAi 当前画布主题。

## 用户流程

1. 用户上传参考视频并点击“开始拉片分析”。
2. 分析期间继续使用顶部工具栏显示阶段和进度。
3. 分析完成后只创建一个“拉片分析”复合节点，并由参考视频节点连接到该节点。
4. 复合节点内部纵向滚动展示全部镜头，不允许修改分析字段。
5. 节点底部固定“下一步：替换元素”按钮，点击后触发现有的分镜提示词策划流程。
6. 后续生成的策划、提示词和视频节点继续在画布中从该复合节点向右展开。

## 节点布局

- 默认宽度约 1320px、高度约 760px，允许用户按现有画布规则缩放节点。
- 标题区显示“拉片分析”、视频标题、总时长、画幅、镜头数量和整体钩子。
- 主体区域为纵向滚动容器，每个镜头占一行，使用六列信息结构：
  1. 代表帧、镜头编号和画面描述；
  2. 叙事要素：场景、角色、动作、对白、可见文字和叙事功能；
  3. 时间：开始、结束和时长；
  4. 镜头语言：景别、构图、机位、镜头与焦点、运镜；
  5. 影像处理：光影、色彩和转场；
  6. 声音：音乐、音效和声音的叙事作用。
- 行与行之间使用低对比度分隔线，不再嵌套独立卡片。
- 底部操作区固定在节点内部，不随镜头列表滚走。
- 浅色和深色模式均使用现有 `canvasThemes`，不复制参考图中的粉色品牌色。

## 数据结构

- 继续使用 `CanvasNodeType.Text`，通过 `metadata.viralVideoAnalysis` 判断为拉片复合节点，不新增新的全局节点类型。
- 在节点 metadata 中新增 `viralVideoShotFrames` 数组，每项包含镜头索引、图片内容地址、存储键、宽高和 MIME 类型。
- 完整分析 JSON、实际拉片请求提示词和代表帧都保存在同一个节点中。
- `workflow.analysisNodeId` 继续指向该复合节点。
- 不再写入 `workflow.analysisShotNodeIds`，也不再创建逐镜头图片节点、逐镜头文本节点及它们之间的连接。

## 渲染边界

- 新建专用 `ViralVideoAnalysisNodeContent` 组件，放在 `web/src/components/canvas/`。
- `project.tsx` 只负责生成分析数据、抽取代表帧、组装单个节点并处理“下一步”动作。
- `CanvasNode` 继续使用现有 `renderNodeContent` 扩展点渲染复合内容，不把业务布局堆进通用节点组件。
- 节点只读：双击不进入文本编辑状态；原始完整提示词可通过节点信息入口查看，不占用主界面空间。

## 交互与状态

- 鼠标滚轮位于镜头列表上时只滚动节点内部，不能带动画布缩放或平移。
- 代表帧缺失时显示“代表帧提取失败”，不影响其余字段和下一步操作。
- 分析没有镜头时沿用现有解析校验并停止创建节点。
- “下一步：替换元素”仅在分析完成且工作流未运行时可点击；运行时显示禁用状态。
- 切换参考视频或重新分析时，保留历史节点的现有策略不变，新结果生成新的复合节点并更新工作流活动节点引用。

## 验证标准

- 一次拉片分析只新增一个分析节点和一条“参考视频 → 拉片分析”连接。
- 多镜头数据完整显示在同一个可滚动节点内，不产生逐镜头画布节点。
- 六列字段与 `ViralVideoAnalysis.shots` 一一对应，代表帧按照镜头索引正确匹配。
- 点击底部按钮进入现有策划流程，不重新调用拉片模型。
- 桌面宽屏下信息可扫描；节点缩小时允许横向内容保持最小列宽并在内部滚动，不压坏文字。
- 深色和浅色主题无硬编码冲突；加载、缺帧、禁用和空值状态均清晰。
