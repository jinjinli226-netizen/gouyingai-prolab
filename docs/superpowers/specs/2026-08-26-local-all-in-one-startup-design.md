# GouYingAi 本地一体启动设计

## 目标

解决前端仍在运行、Gateway 已停止时，管理后台误显示“渠道 0 / 模型 0”的问题。现有 4 个渠道、11 个模型和加密 API Key 继续保存在 `gateway/data/local-store.json`，不复制到前端源码。

## 方案

1. 在项目根目录提供唯一的本地启动脚本，同时启动 Gateway 和 Vite 前端。
2. 启动脚本使用项目内已有 Node、Vite 和 tsx 入口，不引入新的进程管理依赖。
3. 启动前检查 3000、8788 端口：已有服务则复用，缺失服务才启动，避免重复进程。
4. 任一子进程异常退出时输出明确服务名；启动器退出时关闭由它创建的子进程。
5. 管理后台加载失败时保留明确的 Gateway 离线错误状态，不把请求失败渲染成真实的空目录。

## 数据流

```text
统一启动器
├─ Gateway :8788 → local-store.json（渠道、模型、加密 Key）
└─ Vite :3000 → /admin/*、/v1/models → Gateway
```

前端只读取 Gateway 发布目录。没有恢复浏览器本地渠道配置，也不允许模型失败后自动回退。

## 错误处理

- Gateway 未启动或请求失败：后台展示连接错误及重试按钮，渠道/模型计数显示为不可用，不显示为 0。
- 本地数据确实为空：请求成功后才显示“渠道 0 / 模型 0”。
- 端口被其他程序占用：启动器明确指出端口和服务，不覆盖或终止未知进程。

## 验证

- 启动器可同时提供 `http://127.0.0.1:3000` 和 `http://127.0.0.1:8788/v1/models`。
- 管理后台成功读取现有 4 个渠道与 11 个模型。
- 停止 Gateway 后，后台显示离线错误而不是空目录。
- 恢复 Gateway 后点击重试即可重新显示原目录。
