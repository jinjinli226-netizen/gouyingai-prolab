# 持久化多画布生成任务中心设计

## 状态

已确认方向，待书面评审后进入实施计划。

## 背景

当前画布把生成请求、轮询器和取消控制器保存在 `web/src/pages/canvas/project.tsx` 的页面组件中。页面刷新时，`resetInterruptedGeneration` 会把所有 `loading` 节点直接改成错误状态，并显示“页面刷新后生成已中断，请重新生成”。爆款复刻在切换画布或卸载页面时还会主动取消分析、策划和视频任务。

画布项目当前又以完整 `projects` 数组写入同一个 localForage 键。多个浏览器标签页各自持有一份内存快照，任意标签页保存时都可能覆盖另一个标签页刚生成的结果。

目标不是让前端在刷新后重新发起请求，而是让 Gateway 成为生成任务的唯一执行者和真实状态源。

## 已确认需求

- 每个画布是独立的任务空间，任务必须绑定用户、画布、目标节点和生成版本。
- 用户可以在任意多个画布提交任意数量的任务；前端不设置任务数量或并发上限。
- 实际并发、排队、重试和公平调度由 Gateway/服务器配置。
- 文本、图片、视频、音频，以及爆款复刻的拉片、策划和成片阶段全部后台化。
- 切换画布、刷新页面、关闭浏览器后任务继续执行。
- 使用远程 Gateway 时，关闭本机或电脑关机不影响服务器继续执行；重新登录后恢复任务和结果。
- 同一账号打开多个标签页时不能覆盖、重复或串写画布结果。
- 生产模式使用 Supabase/Postgres 和私有对象存储；本地 Gateway 使用本地持久化存储实现相同 API。

## 物理边界

- “电脑关机后继续生成”要求 Gateway 部署在持续运行的远程服务器上。
- 如果使用本机 Gateway，关机期间进程无法继续执行同步的文本、图片和音频请求；已提交给异步上游的视频任务可在 Gateway 重启后恢复轮询。
- 页面只有在素材上传完成且 Gateway 返回持久化 `jobId` 后，才显示“已提交”。处于“上传中”的任务不能承诺关闭浏览器后继续。

## 总体架构

```text
浏览器画布
  ├─ 创建稳定的 canvasId / nodeId / generationRevision
  ├─ 把本地图片、视频、音频上传到私有对象存储
  ├─ POST /v1/canvas-jobs（clientRequestId 幂等）
  └─ 通过任务中心查询/SSE 接收状态并幂等合并结果

Gateway API
  ├─ 认证、归属校验、任务入队
  ├─ 画布快照与结果补丁持久化
  ├─ 素材签名上传/下载
  └─ 管理后台运行参数

Gateway Worker
  ├─ 数据库原子领取任务和租约续期
  ├─ 按服务器配置控制全局/能力/渠道并发
  ├─ 执行文本、图片、视频、音频处理器
  ├─ 持久化上游任务号、阶段、进度、错误和结果
  └─ 把短效上游结果复制到永久私有存储后再标记成功

Postgres / LocalStore
  ├─ 每个画布一条独立记录和单调 revision
  ├─ durable jobs / job events / result patches
  └─ worker lease / idempotency / retry metadata

私有对象存储
  ├─ 用户输入素材
  ├─ 分析代表帧和中间产物
  └─ 最终图片、视频、音频文件
```

## 核心数据模型

### `gouyingai_canvas_projects`

沿用现有表，增加：

- `revision bigint not null default 0`：服务端单调版本。
- `deleted_at timestamptz null`：软删除，避免运行中任务写回已删除画布。
- `payload jsonb`：画布节点、连线、工作流和展示状态，不保存大文件 Base64。

生产环境的服务端记录是跨设备真实源；浏览器按画布 ID 分别缓存，不再把全部画布写进一个大对象。

### `gouyingai_canvas_jobs`

- `id uuid`：Gateway 任务号。
- `user_id uuid`、`canvas_id text`：所有权和画布隔离。
- `parent_job_id uuid null`：批量任务和多阶段工作流归属。
- `target_node_id text`：结果写入目标节点。
- `generation_revision bigint`：节点本次生成版本，防止旧结果覆盖新结果。
- `client_request_id text`：客户端幂等键；对同一用户唯一。
- `kind text`：`text`、`image`、`video`、`audio`、`viral-analysis`、`viral-plan` 或 `viral-video`。
- `status text`：`uploading` 不入库；入库后为 `queued`、`leased`、`submitting`、`running`、`succeeded`、`failed`、`cancel_requested`、`cancelled`。
- `model_id uuid`、`channel_id uuid`：提交时解析出的明确模型和渠道。
- `input jsonb`：不可变的提示词、参数、服务端素材 ID 和业务快照。
- `upstream_task_id text null`：异步上游任务号。
- `result jsonb null`：结构化结果和永久素材 ID。
- `result_patch jsonb null`：对画布的幂等节点/工作流补丁。
- `error jsonb null`：稳定错误码、用户文案和上游摘要。
- `attempt integer`、`max_attempts integer`。
- `lease_owner text null`、`lease_expires_at timestamptz null`、`heartbeat_at timestamptz null`。
- `queued_at`、`started_at`、`finished_at`、`created_at`、`updated_at`。

唯一约束：`(user_id, client_request_id)`。索引覆盖 `(status, queued_at)`、`(user_id, canvas_id, updated_at)` 和租约过期查询。

### `gouyingai_canvas_job_events`

记录状态变化和用户可见阶段，不保存密钥或完整上游响应。任务中心可用它恢复进度和审计重复提交问题。

### 私有素材

复用 `gouyingai-media` 私有 bucket，路径采用：

```text
{userId}/canvas/{canvasId}/jobs/{jobId}/{input|output|intermediate}/{fileId}
```

数据库只保存对象路径、MIME、大小、校验和、宽高/时长。Gateway 不允许任务输入引用其他用户路径。

## 服务端 API

### 任务

- `POST /v1/canvas-jobs`：幂等创建单任务、批次或工作流父任务。
- `GET /v1/canvas-jobs?canvasId=&status=&cursor=`：当前用户任务列表。
- `GET /v1/canvas-jobs/:id`：任务详情，必须校验 `user_id`。
- `POST /v1/canvas-jobs/:id/cancel`：请求取消。
- `POST /v1/canvas-jobs/:id/retry`：使用新的 `clientRequestId` 创建新版本任务，不复用已计费请求。
- `GET /v1/canvas-job-events`：SSE；断线后使用事件 ID 补拉。SSE 不是唯一状态源，页面始终可以用列表接口恢复。

### 画布

- `GET /v1/canvases`：画布索引和任务摘要。
- `GET /v1/canvases/:id`：画布快照及服务端 revision。
- `PATCH /v1/canvases/:id`：携带 `expectedRevision` 的节点/连线补丁；冲突时返回最新 revision，由客户端按节点版本合并。
- `DELETE /v1/canvases/:id`：软删除并按策略取消尚未提交给上游的任务。

### 素材

- `POST /v1/canvas-artifacts/upload-ticket`：返回限定用户、画布、文件大小和 MIME 的短期签名上传信息。
- `POST /v1/canvas-artifacts/complete`：校验对象存在、大小和校验和后登记素材。
- 结果下载使用短期签名 URL；任务记录保存永久对象路径而不是短效 URL。

## 任务状态机

```text
浏览器本地 uploading
        │ 素材完成 + Gateway 接受
        ▼
queued ──领取──> leased ──提交前──> submitting ──> running
   │                 │                  │             │
   ├─取消────────────┴──────────────> cancelled      │
   │                                                   │
   └──────────────────────────── succeeded <───────────┤
                                  failed <─────────────┘
```

- `submitting` 单独存在，用于识别“上游可能已接受但 Gateway 尚未保存任务号”的不确定窗口。
- 只有确认请求未到达上游的错误才能自动重试。
- 请求可能已被上游接受但响应丢失时，任务进入需要对账的失败状态，禁止自动再次付费提交。
- 取消运行中任务时，Gateway 尝试调用上游取消接口；上游不支持时标记 `cancel_requested`，结果返回后保存但不自动覆盖画布。

## 调度与并发

- 前端不限制每个画布或用户的提交数量。
- Gateway 配置全局并发、各能力并发和各渠道并发；有效并发取三者允许值的最小值。
- 默认采用用户间轮转、用户内部按画布轮转、画布内部 FIFO，防止单个画布的大批次长期阻塞其他画布。
- 多个 Gateway 实例通过数据库原子领取函数获取任务；使用租约和心跳，禁止仅依赖内存 Map。
- Worker 崩溃后，过期租约任务由其他实例恢复。已有 `upstream_task_id` 的任务只恢复轮询，不重新提交。
- 管理后台修改并发配置只影响后续领取，不中断正在执行的任务。

## 模型和费用安全

- 创建任务时必须从已发布目录解析唯一 `model_id` 和 `channel_id`。
- Worker 执行时再次检查该模型和渠道仍有效；失效则明确失败，不自动切换模型、渠道或能力。
- 任务输入不保存 API Key，Worker 执行时从 Gateway 加密渠道配置读取。
- 每次可能产生费用的提交都带内部幂等键；上游支持幂等头时同步传递。
- 用量记录绑定 `job_id`，同一付费提交只记一次。

## 各能力执行规则

### 文本

Worker 执行完整非流式请求并保存最终文本。任务中心可以展示阶段，但刷新后不恢复逐 token 动画。返回结果通过 `result_patch` 写入预先分配的文本节点。

### 图片

Worker 使用服务端素材 ID 解析参考图，调用生图接口，把上游 Base64 或短效 URL 转存到私有对象存储，再标记成功。

### 视频

Worker 保存 Gateway 内部任务号和上游任务号。重启后从 `upstream_task_id` 继续轮询；上游结果必须先转存。现有 `gouyingai_gateway_tasks` 的视频映射能力并入统一任务中心。

### 音频

Worker 执行音频请求并将结果转存。超时不代表可以安全重试，重试规则与上游幂等能力绑定。

### 爆款复刻

一个工作流父任务包含有依赖关系的阶段任务：

```text
素材就绪 → 拉片分析 → 每套原创策划 → 每套单次完整成片生成
```

- 原视频和商品图先上传服务端。
- OpenAI 兼容分析需要的代表帧在提交任务前由浏览器提取并上传，或由部署了 FFmpeg 的 Gateway 提取；任务必须记录实际采用的方式。
- 每套创意仍然只创建一个付费视频任务。
- 子任务失败不会删除其他成功变体；父任务汇总成功、失败和取消数量。

## 画布结果合并

- 提交前先为输出分配稳定 `nodeId`，节点保存 `jobId` 和 `generationRevision`。
- Gateway 结果补丁只能修改该任务声明的目标节点和工作流字段。
- 客户端或 Gateway 应用补丁前同时校验 `canvasId`、`nodeId`、`jobId` 和 `generationRevision`。
- 用户重新生成时 revision 加一；旧任务即使晚返回也只保留在任务记录中，不覆盖新结果。
- 画布已删除时结果保留到任务中心的保留期，不自动重建画布。
- 目标节点被用户删除时结果标记为“产物未挂载”，用户可从任务中心手动恢复为新节点。

## 浏览器本地状态与多标签页

- IndexedDB 改成画布索引和每画布独立记录，禁止整包覆写全部项目。
- 每条本地记录带服务端 revision 和客户端实例 ID。
- `BroadcastChannel` 只用于及时通知其他标签页重新读取；真实冲突判断仍以服务端 revision 为准。
- 页面打开、恢复网络、SSE 重连和窗口重新获得焦点时都执行任务对账。
- 删除现有“刷新后把 loading 全部改成 error”的逻辑；有 `jobId` 的节点从服务端恢复，无 `jobId` 的旧版 loading 节点才标记为无法恢复。

## 任务中心 UI

- 全局入口展示所有画布的上传中、排队中、运行中、成功、失败和取消任务。
- 每条任务显示画布名称、能力、模型、阶段、提交时间、开始时间和结果。
- 点击任务跳转并聚焦对应画布节点。
- 用户可以取消排队任务、请求取消运行任务、重试失败任务、恢复未挂载产物。
- 节点上的状态文案来自服务端任务，不再根据页面是否刷新判断。

## 安全修复

- 所有任务、结果、画布和素材接口必须校验当前认证用户所有权。
- 修复现有 `/v1/videos/:id` 和 `/content` 未比较 `task.user_id` 的问题。
- 生产环境 CORS 使用允许域名列表，不使用无限制 `cors()`。
- Gateway 只接受私有存储中的当前用户素材，禁止任意 URL 服务器端抓取，降低 SSRF 风险。
- 日志不记录令牌、API Key、完整私有提示词、Base64 素材和签名 URL。
- 上传票据限制 MIME、大小、对象路径和有效期。

## 故障处理

| 故障                   | 行为                                         |
| ---------------------- | -------------------------------------------- |
| 浏览器刷新/关闭        | 服务端任务不受影响，重新打开后对账           |
| Gateway Worker 崩溃    | 租约过期后恢复；有上游任务号时只轮询         |
| Gateway 在提交窗口崩溃 | 进入不确定状态并对账，禁止盲目重复付费       |
| 数据库暂时不可用       | 停止领取新任务；不以内存成功代替持久化成功   |
| 对象存储上传失败       | 不创建可执行任务，浏览器显示上传失败         |
| 上游短效 URL 失效      | 转存失败则任务失败，不生成不可播放的成功节点 |
| 模型或渠道被禁用       | 排队任务明确失败，不自动回退                 |
| 旧任务晚返回           | revision 不符，结果保留但不覆盖节点          |
| 多标签页同时编辑       | expectedRevision 冲突后重新读取和按节点合并  |
| 画布/节点被删除        | 任务结果成为未挂载产物，不自动复活数据       |

## 本地 Gateway

- 使用与生产模式相同的 API 和状态机。
- LocalStore 增加 canvases、jobs、events、settings 和 artifacts 索引。
- 文件保存采用临时文件写入、`fsync` 后原子 rename，避免进程中断破坏整个 JSON。
- 本地单进程不需要数据库抢占，但仍使用 lease 字段保证重启恢复逻辑一致。
- 本地素材保存在 Gateway 数据目录，不再只存在浏览器 IndexedDB。

## 管理后台配置

新增 Gateway 运行配置：

- 全局执行并发。
- 文本、图片、视频、音频能力并发。
- 每个渠道并发和最小请求间隔。
- Worker 租约、心跳、任务超时和最大安全重试次数。
- 任务事件、输入素材、中间产物和最终产物保留期。
- 用户存储额度和单文件大小限制。
- 生产前端允许域名。

这些配置只存在服务器端，前端只读取任务状态，不决定并发。

## 迁移顺序

1. 新增数据库任务、事件、revision、调度配置和原子领取函数。
2. 扩展 LocalStore，实现同一任务仓库接口。
3. 新增 Gateway 任务 API、素材 API、Worker 和能力处理器。
4. 先接通单节点文本/图片/视频/音频任务，保留旧接口但画布不再直接调用。
5. 接通爆款复刻父子任务和批量工作流。
6. 前端改为每画布独立缓存、任务中心和结果对账。
7. 删除页面卸载取消逻辑和 `resetInterruptedGeneration` 的一刀切失败行为。
8. 限制旧视频查询接口的任务所有权和生产 CORS。

迁移期间，旧版没有 `jobId` 的 `loading` 节点无法安全恢复，只能保留明确的旧任务中断提示；新提交任务全部使用持久化任务中心。

## 实施子项目

该目标拆成四个连续交付、分别测试的子项目，避免跨层大爆炸式修改：

1. **耐久任务内核与安全基线**：数据库迁移、任务仓库、幂等创建、所有权校验、原子领取、租约、后台并发配置和现有视频任务越权修复。
2. **服务端素材与能力处理器**：私有素材上传、永久结果转存，以及文本、图片、视频、音频四种单任务处理器。
3. **画布持久化与任务中心**：每画布独立缓存、服务端 revision、跨标签页通知、任务对账、节点状态恢复和全局任务中心。
4. **业务工作流迁移**：把通用批量生成、珠宝、海报、电商和爆款复刻迁移为父子任务/DAG，并移除页面生命周期取消逻辑。

每个子项目都必须保持旧路径可运行，只有对应新路径通过恢复测试后才切换入口；禁止在同一能力内随机混用前端执行和 Gateway 执行。

## 测试策略

### Gateway 单元/集成测试

- `clientRequestId` 重复提交只创建一个任务。
- 不同用户不能读取、下载、取消或重试对方任务。
- 两个 Worker 不能领取同一任务。
- Worker 崩溃后租约恢复，不重复提交已有上游任务号的任务。
- 并发配置和跨画布公平调度生效。
- 旧 revision 结果不能覆盖新节点。
- 短效结果只有在转存成功后才能标记成功。
- 模型失效、素材越权、画布删除和取消状态正确。

### 前端测试

- 刷新后有 `jobId` 的节点保持排队/运行状态，不变成中断错误。
- 多个画布的任务分别合并到对应节点。
- 多标签页通知不会覆盖其他画布的更新。
- SSE 断开后通过列表接口补齐事件。
- 旧结果、重复事件和重复结果补丁保持幂等。
- 任务中心跳转、取消、重试和恢复未挂载产物正确。

### 验收场景

1. 在画布 A 提交图片生成，切到画布 B 提交视频，两个任务都继续。
2. 同时打开多个标签页，各自提交不同画布，结果不互相覆盖。
3. 提交后刷新、关闭浏览器并重新打开，任务状态和结果恢复。
4. 使用远程 Gateway 时关闭本机，任务在服务器完成，重新登录后写回正确节点。
5. Gateway 在排队、提交、轮询、转存各阶段重启，均不重复扣费或丢失任务。
6. 同一节点连续重新生成两次，较旧结果不能覆盖较新结果。
7. 删除节点或画布后任务完成，产物进入未挂载状态而不复活已删除内容。

## 架构决策记录

### ADR-001：Gateway 是生成任务执行者

**决定：** 浏览器只上传素材、提交任务和显示状态；所有付费模型请求由 Gateway Worker 执行。

**原因：** 只有持续运行的服务器能够满足页面关闭和电脑关机后继续执行。

**代价：** 需要任务队列、对象存储、Worker 运维和数据库迁移。

### ADR-002：Postgres 是生产任务真实源

**决定：** 不使用浏览器、内存 Map、SSE 或 Redis 作为唯一任务状态源；生产任务以 Postgres 持久化记录为准。

**原因：** 支持重启恢复、幂等、所有权审计、多个 Worker 原子领取和跨设备查询。

**代价：** 所有任务状态变化都需要可靠数据库写入。

### ADR-003：按画布和节点版本应用结果

**决定：** 每个结果补丁必须携带 `canvasId + nodeId + jobId + generationRevision`。

**原因：** 防止任务串画布、旧结果覆盖新结果和重复事件创建重复节点。

**代价：** 画布数据结构和所有生成入口都需要统一接入任务元数据。

## 非目标

- 不在首版实现跨账号共享画布或多人实时协同编辑。
- 不承诺所有上游都支持真正取消或退款。
- 不通过前端并发限制代替服务器调度。
- 不把大文件、Base64、API Key 或完整上游响应保存进任务 JSON。
