# GouYingAi 使用与维护手册

GouYingAi 是一个把提示词、图片、视频、资产和 AI 生成流程放在同一张无限画布中的创作工作台。本手册前半部分讲日常使用，后半部分讲渠道、模型与故障维护。

> [!IMPORTANT]
> 当前版本不需要注册账号。API Key、渠道配置、画布、资产和生成记录默认保存在当前浏览器的本地数据中。清理站点数据、改用无痕窗口、换浏览器或换设备，都不会自动带走这些数据。

## 快速开始

1. 打开右上角的 **配置**。
2. 在 **渠道** 中填写 Base URL、API Key 和调用格式。
3. 拉取模型，或手动输入服务商提供的准确模型名。
4. 在 **模型** 中把模型加入可选项，并设置默认的生图、视频、文本和音频模型。
5. 回到生图、视频或画布页面开始创作。

### 配置字段说明

| 字段 | 作用 |
| --- | --- |
| 渠道名称 | 仅用于识别，例如“主渠道”或“视频渠道”。 |
| Base URL | 服务商提供的 API 根地址。通常填域名根路径；如果地址已以 `/v1`、`/api/v3` 或 `/api/plan/v3` 结尾，不要重复添加。 |
| API Key | 该渠道的访问令牌。仅保存在本机浏览器中。 |
| 调用格式 | 大多数 OpenAI 兼容服务选 **OpenAI**；只有服务商要求 Gemini 原生格式时才选 **Gemini**。 |
| 模型列表 | 该渠道实际可调用的模型。相同模型名放在不同渠道时，系统会保留各自的 Base URL 和 API Key。 |

## 日常创作

### 生图工作台

在 **生图** 页面选择模型，输入提示词后生成。上传参考图时，系统会根据模型能力发送图生图或编辑请求。生成结果会保留提示词、模型和主要参数，方便重新生成或放入资产库。

建议先用一句清楚的主体描述，再补充画面、光线、构图、镜头和风格。例如：

```text
雨后的城市街道，霓虹灯倒映在积水里，低机位缓慢推进，电影感冷暖对比，细节清晰
```

### 视频创作

在 **视频** 页面填写提示词，按模型支持情况上传参考图、参考视频或参考音频，然后提交任务。视频生成是异步任务，页面会自动轮询进度；不要在任务运行时关闭页面或清理浏览器数据。

不同视频模型支持的能力不同，以页面实际可选项为准。常见规则如下：

| 模型类型 | 参考素材与参数 |
| --- | --- |
| 普通 OpenAI 兼容视频模型 | 通常支持文生视频，是否支持参考图、时长和清晰度取决于上游。 |
| `grok-imagine-video` | 不带图为文生视频；带 1-7 张图为图生或多图参考。支持 6、10、12、16、20 秒。 |
| `omni-fast` / `omni-fast-no-water` | 文生或图生；最多 5 张参考图。固定 720p、约 10 秒，仅支持 16:9 或 9:16。 |
| `omni-fast-v2v` / `omni-fast-v2v-no-water` | 视频转视频；最多 2 个参考视频，每个不超过 8MB。 |

`omni-fast` 的“720p · 横屏/竖屏 · 约10s”是该模型真实限制，不会因为全局默认值显示为方形或 6 秒而改变实际提交参数。

### 在无限画布中工作

画布适合把创作过程串成可复用的链路：文本节点放提示词和脚本，图片/视频节点放参考素材与生成结果，配置节点负责模型和参数。

1. 新建画布后，拖入图片、视频或音频，或从工具栏新增文本节点。
2. 用节点两侧的连接点把文本、参考素材连接到生成配置节点。
3. 在配置节点选择模型和参数，预览输入内容后执行生成。
4. 结果会作为新的图片、视频、文本或音频节点回写到画布，可继续连接到后续步骤。

常用操作：拖动空白处平移画布，滚轮缩放，`Ctrl/Cmd + A` 全选，`Ctrl/Cmd + C/V` 复制粘贴，`Ctrl/Cmd + Z` 撤销，`Delete/Backspace` 删除选中内容。

### 反推提示词

选中已有图片或视频节点后，可使用节点工具栏中的 **反推提示词**。系统会创建对应的文本和配置节点，由当前文本模型分析素材并生成可编辑的描述。

要得到更有用的视频反推结果，文本模型需要具备视觉或视频理解能力。提示词中可以要求它按镜头拆分，例如：

```text
分析这个视频的主体、环境、镜头运动、转场、光线、节奏和每个分镜的动作；输出可直接用于视频生成的分镜提示词。
```

长视频的理解质量和可上传大小取决于上游服务。若模型只返回简短描述，通常是上游只提取了部分帧，或该模型不具备完整视频理解能力，并非画布会自动按总时长生成分镜。

### 资产与提示词中心

**资产** 用于沉淀图片、视频、文本、音频与常用提示词。可以从画布节点、生成结果或提示词中心保存资产，再搜索、筛选并插回画布。

**提示词中心** 用于检索、复制和复用提示词。把稳定有效的提示词保存到资产后，后续可直接插入画布或创作工作台。

### 备份与同步

- 单个画布可导出为文件，并可重新导入。
- 配置 WebDAV 后，可以同步画布、资产、生成记录和本地媒体文件。
- WebDAV 不会同步 API Key；在新设备上仍需重新填写渠道密钥。

## 维护渠道与模型

GouYingAi 支持两种运行模式：

- **平台固定模型（推荐）**：管理员在 `/admin` 管理后台维护渠道和模型，API Key 只保存在服务端网关中。用户登录后自动看到已发布的模型，无需自己填写 Base URL、Key 或模型名，所有 AI 请求统一经过网关转发。
- **本地自带 Key**：开发者或单机用户可以在配置里手动添加 OpenAI 兼容渠道。该模式下数据仍只保存在浏览器本地，适合开发调试。

### 平台固定模型（网关模式）

先介绍最快捷的**本地模式**：网关和后台不需要 Supabase 就能跑起来。

1. 在 `gateway/.env` 设置 `GATEWAY_LOCAL_MODE=1` 和 `GATEWAY_ENCRYPTION_KEY`，运行 `cd gateway && npm install && npm run dev`。
2. 在 `web/.env` 设置 `VITE_GATEWAY_URL=http://127.0.0.1:8788`。
3. 打开 `/admin` 即可直接使用后台，新增渠道（Base URL + API Key）和固定模型；数据保存在 `gateway/data/local-store.json`，AI 请求同样经过网关转发。

本地模式适合先跑通业务；要上线给用户使用，再切换为下面的云端模式：

1. 部署 Supabase 并执行 `supabase/migrations` 下的迁移，配置 Auth、RLS 和私有 Storage。
2. 部署 `gateway/` 网关服务，设置 `SUPABASE_URL`、`SUPABASE_ANON_KEY`、`SUPABASE_SERVICE_ROLE_KEY` 和 `GATEWAY_ENCRYPTION_KEY`。
3. 在前端设置 `VITE_SUPABASE_URL`、`VITE_SUPABASE_ANON_KEY` 和 `VITE_GATEWAY_URL`。
4. 在 Supabase 的 `gouyingai_admins` 表中把自己的用户 ID 添加为管理员。
5. 打开 `/admin`，用邮箱登录链接进入后台，新增渠道（Base URL + API Key）和固定模型，选择能力（图像/视频/文本/音频）、发布状态与排序。

网关会把渠道 Key 加密保存，浏览器永远拿不到真实 Key。每次调用由网关校验登录状态、按模型名找到对应渠道并转发，同时记录用量。

### 多渠道原则

每个模型都绑定到一个具体渠道。即使两个渠道显示为同一个域名，也可能使用不同的 Key、调用格式或服务商后台模型权限。添加模型时建议按用途拆分渠道，例如文本理解、生图、视频和备用渠道。

同名模型在多个渠道中出现时，模型下拉列表会带有渠道序号、域名和 Key 后四位。选择时必须确认选中的是预期渠道，不要只看模型名称。

### 调用格式选择

| 场景 | 应选择的格式 |
| --- | --- |
| 服务商说明“OpenAI 兼容”，端点包含 `/v1/chat/completions`、`/v1/images` 或 `/v1/videos` | OpenAI |
| 服务商要求 Gemini 原生 `generateContent` 协议 | Gemini |
| Gemini 系列模型但服务商提供 OpenAI 兼容转发 | OpenAI |
| 视频生成，包括 Omni 与 Grok 视频 | OpenAI |

例如 Gemini Flash 被服务商包装为 OpenAI 兼容接口时，模型名填服务商给出的精确名称，调用格式仍选 **OpenAI**。把它设为文本模型后可用于提示词改写、图片理解或视频反推；前提是该渠道实际开放了对应的多模态能力。

### Omni 视频模型接入

Omni 使用 OpenAI 兼容的异步视频接口：提交到 `POST /v1/videos`，随后轮询 `GET /v1/videos/{task_id}`。管理员只需在渠道中配置正确的 Base URL、API Key 和 **OpenAI** 格式，再把以下模型名加入该渠道：

```text
omni-fast
omni-fast-no-water
omni-fast-v2v
omni-fast-v2v-no-water
```

带水印与无水印模型在供应商后台通常是两条独立渠道。`omni-fast` 能用而 `omni-fast-no-water` 失败，不代表前端参数错误；应检查无水印模型是否被该 API Key、令牌分组和上游渠道实际授权。

### 价格与计费

GouYingAi 不内置供应商价格表或余额扣费逻辑。每一次真实生成都由上游服务商计费，价格、失败是否收费、配额和速率限制均以渠道后台为准。建议先使用低成本模型完成链路验证，再切换到正式模型。

## 常见问题

### 拉取模型后列表为空

先确认 Base URL、API Key 和调用格式。若请求成功但返回空模型列表，通常是令牌没有模型权限、令牌分组不匹配，或该服务商不开放 `/v1/models`。对于不提供模型列表的渠道，直接手动添加模型名即可。

### 提示“鉴权失败”

检查 API Key 是否有效、是否有余额或套餐权限，以及当前模型是否在该令牌的分组内。不要把 API Key 粘贴到公开截图、文档或聊天记录中；已泄露的 Key 应立即在服务商后台轮换。

### 提示“本地中转无法连接到配置的上游地址”

这表示本机开发服务无法建立到该渠道 Base URL 的网络连接，尚未进入模型参数校验。依次检查完整 Base URL、域名解析、网络代理、HTTPS 证书和渠道是否实际可访问。若同一时刻另一个模型可用，应重点检查失败模型实际绑定的渠道，而不是只比较界面上被截断的域名。

### 视频任务失败或长时间不完成

确认模型、参考素材类型、大小、比例和时长符合服务商限制。视频任务通常需要数分钟；不要频繁重复提交。只有在上游明确返回失败后再重试，并以渠道后台的任务详情作为最终依据。

### 数据丢失或新设备没有画布

本地数据不会自动跨设备同步。已配置平台账号时，登录后可从 Supabase 恢复画布、资产和生成记录；否则优先从画布导入文件恢复，或在旧设备先配置 WebDAV 并完成同步。浏览器缓存清理前必须先完成导出或同步。

## 安全边界

- 不要在公共设备、共享浏览器或不可信页面中保存 API Key。
- 不要把 Key 写入提示词、画布文本、截图、导出文件或公开文档。
- 网关模式下，Key 只保存在服务端并加密；前端请求只携带用户的登录令牌。
- 公开部署给多人使用前，应确认 Supabase RLS、存储策略和管理员角色已正确配置，并开启用量控制。
